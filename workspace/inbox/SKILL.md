# 事项收件箱 (inbox)

## 数据
- 总清单：`~/workspace/goals/goal/hidden_files/inbox.json`（本地 JSON，事项唯一真相源）
- 分类（固定 6 个，不新增）：杭州落户 / 学习考试 / 项目主线 / 合作人际 / 知识资产 / 工具设备
- 优先级：P0（有硬 deadline，过期会出事）/ P1（重要推进中）/ P2（长期或等料）
- 状态：open（进行中）/ waiting（等裁决·等料·等超哥）/ done（超哥已确认完成）

## Intake 协议（超哥在聊天里丢新事项时执行）
1. **先判断**：是不是新事项？闲聊、提问不算；已有事项的进展更新不算新事项——找到对应条目更新 notes 即可。
2. **去重**：用关键词对照 inbox.json 现有事项（title + notes）。疑似重复 → 先问超哥合并还是单独立项，不自作主张建两条。确认重复的记入 dedup_log。
3. **分类定级**：按 6 分类归；P0 只给"有明确日期且过期会出事"的。
4. **写入**：id 用 meta.next_id 递增（inbox-017…），source 标注 chat / voice / forward，created_at 写当天日期；明显在等人的标 waiting，其余默认 open。
5. **确认**：简短一句——"已收录 inbox-017标题"。不展开、不分析。

## 铁律
- 只做分类、排序、合并；**不删除、不关闭任何事项**。done 只能是超哥亲口确认完成的事。
- 事项内容只存本地，不向外部服务发送。
- 语音转写只处理超哥主动发来的内容。
- 每周复盘由定时任务 weekly-inbox-review 执行，intake 不碰复盘逻辑。
- 超哥说停 → 停用 intake 并关闭定时任务；目标关闭 → 定时任务随目标删除。
